# Food Marketplace — Описание проекта

---

## I. Обзор проекта

### 1.1. Цель проекта

В сфере продовольствия ежедневно большое количество продуктов выбрасывается из-за истечения срока годности — особенно в небольших магазинах, пекарнях и ресторанах, где точно прогнозировать спрос крайне сложно. В то же время многие потребители хотели бы покупать качественные продукты по сниженным ценам, но не имеют удобного канала для этого. Проект Food Marketplace решает эту проблему, создавая платформу, которая связывает продовольственные магазины с покупателями через систему локеров (умных ячеек хранения). Магазины формируют комбо-наборы из продуктов с истекающим сроком годности со скидкой, размещают их в локерах в удобных местах; покупатели заказывают и оплачивают онлайн, а затем забирают заказ из локера с помощью QR-кода. Эта модель помогает сократить пищевые отходы, создаёт дополнительный источник дохода для магазинов и одновременно приносит экономическую выгоду потребителям — всё через полностью автоматизированный процесс, без необходимости присутствия обслуживающего персонала.

### 1.2. Объекты системы

| Объект | Описание |
|--------|----------|
| **Owner** | Владелец системы (инвестор платформы). Может одновременно владеть физическими локерами или арендовать локеры у третьей стороны. |
| **Shop (owner_shop)** | Владелец продовольственного магазина, публикующий комбо-наборы со скидкой на платформе. |
| **Owner Locker (owner_locker)** | Владелец и управляющий физическими точками локеров. |
| **Customer** | Покупатель, приобретающий комбо и забирающий заказ из локера. |
| **Admin** | Администратор системы, управляющий учётными записями и эксплуатацией платформы. |

**Описание процесса работы:**

1. **Owner** владеет платформой. Owner может напрямую владеть физическими локерами или арендовать локеры у третьей стороны (locker owner).
2. **Shop owner** заключает договор с Owner для участия в платформе. Существуют 2 формы:
   - Заключение договора напрямую с Owner → Owner привязывает магазин к локерам по трёхстороннему соглашению (Owner — Shop Owner — Locker Owner).
   - Заключение договора с Locker Owner → разрешение продавать на локациях, принадлежащих данному Locker Owner.
3. **Admin** создаёт учётные записи для shop owner и locker owner после завершения регистрации договора. Данные учётной записи отправляются на зарегистрированный email.
4. **Locker Owner** привязывает магазины к локациям, управляет ячейками.
5. **Shop Owner** создаёт продукты, формирует комбо-наборы со скидкой, выбирает ячейку для продажи.
6. **Customer** просматривает комбо, оформляет заказ, оплачивает через Fincode, получает QR-код, забирает заказ из локера.

## II. Описание функций по ролям

### 1. Customer (Покупатель)

#### Просмотр и поиск
- Просмотр списка доступных комбо на главной странице
- Просмотр деталей комбо (состав, оригинальная цена, цена со скидкой)
- Просмотр информации о магазине
- Просмотр списка локеров на карте, поиск ближайшего локера

#### Заказ и оплата
- Оформление заказа комбо
- Регистрация платёжной карты через платёжный шлюз Fincode (японский платёжный шлюз с тестовой средой — для регистрации используется карта с номером `4111 1111 1111 1111`). Система перенаправляет на страницу регистрации карты Fincode, данные карты пользователя не сохраняются в системе.
- Онлайн-оплата
- Просмотр истории заказов и деталей каждого заказа

#### Получение заказа
- Получение кода доступа и QR-кода для открытия локера после оплаты
- Открытие локера для получения заказа

#### Взаимодействие
- Добавление/удаление избранных магазинов
- Добавление/удаление избранных локеров
- Написание отзыва (review) на купленное комбо
- Push-уведомления *(не реализовано)*:
  - При публикации нового комбо избранным магазином
  - При успешной оплате без получения заказа → push-уведомление за 10 минут до истечения срока получения

#### Учётная запись
- Регистрация аккаунта
- Вход / Выход
- Просмотр и редактирование личных данных

---

### 2. Shop (Владелец магазина — owner_shop)

#### Управление магазином
- Просмотр и редактирование информации о магазине (название, описание, адрес)
- Загрузка изображения магазина

#### Управление продуктами
- Создание нового продукта (ProductMaster)
- Редактирование информации о продукте
- Загрузка изображения продукта

#### Управление комбо
- Создание комбо (объединение продуктов, установка скидки, выбор ячейки локера)
- Просмотр списка созданных комбо
- Редактирование комбо

#### Распространение
- Выбор ячейки локера для размещения комбо на продажу

#### Статистика и отчётность
- Просмотр истории продаж
- Просмотр выручки по месяцам
- Просмотр списка комбо с различными статусами
- Анализ данных пользователей *(конкретный план не разработан, не применено)*

#### Взаимодействие
- Просмотр отзывов покупателей
- Получение уведомлений при покупке заказа

---

### 3. Owner Locker (Владелец локера — owner_locker)

#### Управление локациями локеров
- Создание новой локации (название, адрес, координаты)
- Редактирование информации о локации
- Загрузка изображения локации

#### Управление ячейками локера
- Добавление ячеек в локацию
- Редактирование информации о ячейке (размер, статус)
- Удаление ячейки

#### Привязка магазинов
- Привязка магазина к локации (разрешение на продажу в локере)
- Просмотр списка комбо, размещённых в ячейках

#### Синхронизация и мониторинг
- Синхронизация данных локеров с Firebase (в реальном времени)
- Просмотр общей панели мониторинга
- Просмотр статистики размещения комбо (какое комбо в какой ячейке)

---

### 4. Admin (Администратор)

#### Управление пользователями
- Просмотр списка всех пользователей
- Фильтрация пользователей по роли
- Создание учётных записей для shop owner и locker owner (после создания система отправляет уведомление по email)
- Изменение роли пользователя

#### Полный доступ к системе
- Доступ ко всем данным: магазины, продукты, комбо, заказы, локеры
- Выполнение всех операций, доступных shop owner и locker owner
- Просмотр общей панели управления продажами

#### Панель статистики и аналитики *(не применено)*

#### Эксплуатация системы
- Синхронизация всех локеров с Firebase
- Мониторинг общей активности маркетплейса

### 5. Функции для эксплуатации в реальной среде

#### Управление параллельным доступом (Concurrency Control)
- Использование **Redis Lock** (распределённая блокировка) для предотвращения одновременной оплаты и покупки одного комбо двумя покупателями. Блокировка применяется по ID комбо с атомарным механизмом (SET NX + EX) и автоматическим истечением.

#### Системное логирование (Audit & System Logging)
- Централизованное логирование событий: аутентификация, системные ошибки, платёжные операции, изменения статуса заказа.
- Для расследования при получении претензий (claim) от покупателей в процессе эксплуатации.

#### Фоновая обработка (Background Jobs)
- Celery + Redis для фоновых задач и планирования:
  - Автоматическая очистка отозванных токенов (каждые 30 минут)
  - Автоматическая обработка комбо с истекшим сроком
  - Автоматическая обработка заказов с просроченным сроком получения (pickup deadline)

#### Оплата и Webhook
- Интеграция с платёжным шлюзом Fincode с механизмом повторных попыток (максимум 3 раза) при вызове API.
- Webhook callback с проверкой подписи (signature verification) для обеспечения целостности данных от Fincode.
- Поддержка аутентификации 3D Secure.

#### Rate Limiting
- Ограничение частоты запросов на основе Redis (скользящее окно) для предотвращения злоупотребления API.

#### Хранение файлов
- Хранение изображений на локальном хранилище (EBS volume при деплое на AWS EC2).
- Валидация MIME-типа (JPEG, PNG, WebP, GIF) и ограничение размера файла.

#### Отправка email
- Интеграция с AWS SES для отправки email (уведомление о создании аккаунта для shop/locker owner).
- HTML-шаблоны email.

#### Health Check
- Эндпоинт `/health` для проверки состояния работы системы, для мониторинга и балансировщика нагрузки.
